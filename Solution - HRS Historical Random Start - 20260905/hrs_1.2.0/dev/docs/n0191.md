## Marker API decision

The later Phase 1A candidate is the game-owned player CVar
`bitwrecked_hrs_state_v1`, using nonzero allowlisted states `Reserved=1`,
`Completed=2`, and `Invalid=3`. Static inspection proves that this API is part
of the player `EntityBuffs` serialization path and does not require platform
identity.

This is an API-route decision, not a persistence pass. Phase 1 does not write
the marker. Phase 1A must prove save timing, reload, reconnect, death, and crash
windows in a disposable target. Failure or uncertainty leaves vanilla spawning
untouched and blocks promotion.

## Core behavior held for Phase 1A

- Standard/Vanilla performs zero reservation, selection, placement, or marker
  work.
- Random is considered only for authoritative `NewGame` and provisionally
  `EnterMultiplayer` events.
- One successful reservation is required before one native list selection.
- The native list is never replaced with arbitrary X/Z generation.
- Empty/undefined/unsafe/unloaded candidates consume the reservation and leave
  the already-established vanilla spawn untouched.
- `Reserved`, `Completed`, malformed, or unavailable marker state never rerolls.
- A placement is never called by the Phase 1 observation probe.
- Expanded Random placement, rooftops, drops, protection, commands, policy
  writes, and Start Game handoff remain outside this packet.
- Starter-quest event handling and nearest-trader destination updates remain
  outside the Phase 1 observation probe and Phase 1A placement proof. They
  require a separately reviewed Phase 1B source/test packet after Phase 1A.
- The preview's two proposed Random-start safeguard scopes do not expand this
  packet. No hazard suppression, character mask, biome candidate, or related
  runtime source enters Phase 1 or Phase 1A. Those safeguards are required for
  the complete two-choice product, but only through a separately reviewed
  Phase 1C packet after Phase 1B.
