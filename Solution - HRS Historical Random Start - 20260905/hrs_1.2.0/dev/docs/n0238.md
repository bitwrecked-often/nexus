## Run contract

1. Use an existing disposable Navezgane save and enable God/invulnerable mode.
2. Close the game.
3. From the repository root, run:

   ```powershell
   .\hrs_1.1.0\dev\qa\Start-HrsCarousel.ps1 `
     -GameName '<exact-save-name>' -DwellSeconds 5
   ```

4. Leave that PowerShell window open. Start 7 Days to Die without EAC and load
   the named existing save.
5. During the 30-second preflight window, enable developer and God/invulnerable
   mode. Then do not walk, jump, fly, or intentionally alter health during the
   series. The runtime rejects health loss or movement beyond three metres
   during preflight as `PREFLIGHT_CHANGED`, before testing any location.
6. The runtime captures the starting position, waits 30 seconds, then visits
   the armed start-to-end range in fixed order. It resolves with
   the catalogued ground Y to load the containing chunk, then resolves with
   `World.GetTerrainHeight`, requires terrain within 24 blocks of catalog Y,
   uses the native spawn check, proves three stable grounded samples, and
   dwells for the armed duration.
7. The runner prints each transition and ends with the exact status, passed
   count, current point, and reason.

With zero rejections, the corrected five-second run contains 745 points and has
a minimum dwell time of 1 hour 2 minutes 5 seconds. Loading and landing checks
add runtime. The watcher defaults to a twelve-hour bound.

After a recorded point failure, close the game, persist the exact rejection,
then resume at the next stable ID:

```powershell
.\hrs_1.1.0\dev\qa\Reject-HrsCarouselPoint.ps1 `
  -PointId NVG-0123 -Reason SETTLE_FAILED

.\hrs_1.1.0\dev\qa\Start-HrsCarousel.ps1 `
  -GameName 'HRS_CAROUSEL_110_001' -DwellSeconds 5 `
  -StartPoint NVG-0124
```

Blank bounds select the first and last active POI. Explicit `StartPoint` and
`EndPoint` must identify active `NVG-####` IDs in catalog order and are recorded
in the consumed arm. Rejected IDs are invalid on later builds. These controls
do not remove or activate any production point.

## Fail-closed behavior

Any anchor-resolution error, chunk timeout, unsafe landing, failure to settle,
position outside world bounds, health loss, runtime exception, or manual stop
ends the series. Before stopping, the carousel attempts to restore the captured
starting position and verifies that restoration within three metres. The final
result distinguishes a point failure from `RESTORE_FAILED`.

For an emergency stop, open another PowerShell window and run:

```powershell
.\hrs_1.1.0\dev\qa\Stop-HrsCarousel.ps1
```

A fully successful series also returns to the captured starting position.

After capturing the evidence and closing the game, remove the QA-only mod:

```powershell
.\hrs_1.1.0\dev\qa\Remove-HrsCarousel.ps1
```

## Interpretation

This test efficiently detects invalid geometry, missing chunks, unsafe
placements, unstable landings, immediate health loss, and runtime failures.
It does not certify random distribution, fresh-character exactly-once behavior,
nearest-trader selection, starter-quest routing, reload persistence, survival
without invulnerability, package identity, installation, or rollback. Those
remain separate release QA cases.
