## Planned feature order

1. Promote an explicit production subset from the 171 certified locations.
   Keep stable IDs and a reviewable allowlist; never make every catalog entry
   selectable by implication.
2. Route the opening quest to the nearest valid trader within the confirmed
   landing biome/zone when possible. If no same-zone trader exists, preserve
   the native objective, record a terminal bounded failure, and do not reroll
   or silently choose a trader from another biome.
3. Preserve the native starter quest, phase, rewards, progression, trader
   inventory, and exactly-once relocation behavior.
4. Implement arrival-biome danger suppression as an independent option and
   failure domain. It must affect only the reviewed biome hazard family and
   must not disable enemies, ordinary damage, weather presentation, or later
   biome hazards outside the selected scope.
5. Test spawn selection, same-zone trader routing, terminal fail-closed routing,
   biome suppression, and combined behavior in separately scored domains before
   packaging.

## Development gates

- Define “zone” operationally before coding. The current working interpretation
  is the confirmed landing biome, not merely straight-line trader distance.
- Inventory trader placement, biome membership, reachability assumptions, and
  random-world limitations before changing routing authority.
- Keep Navezgane coordinates separate from random-generated-world prefab
  identity and placement discovery.
- Add failing contracts before expanding production selection or protection.
- Preserve 1.1.0 and its evidence as immutable history; all new work stays in
  `hrs_1.2.0`.
- Do not build a Nexus archive until the new feature contracts and live QA
  cases pass against exact promoted bytes.
