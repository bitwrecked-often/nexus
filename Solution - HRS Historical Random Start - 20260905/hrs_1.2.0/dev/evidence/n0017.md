## Implemented state design

The preview retains the last Yes-confirmed settings as an immutable in-memory
snapshot. A separate validation state holds the normalized key of the exact
game-folder text that was last checked. UI state is derived from the current
controls, that snapshot, and the checked-folder key:

| Derived state | Meaning and capability |
| --- | --- |
| `FolderCheckRequired` | The path is new or edited. The prior snapshot is visibly stale, and Apply is disabled until the current text is checked. |
| `InvalidFolder` | The checked path does not contain `7DaysToDie.exe`. Apply remains blocked. |
| `NotApplied` | The exact current folder is valid, but no snapshot has been confirmed in this window. |
| `Pending` | The valid live folder/start/safeguard values differ from the last confirmed snapshot. |
| `Applied` | Every live value matches the last confirmed snapshot. This means only applied to the open preview session. |

Cancel is an outcome layered over `NotApplied`, `Pending`, or `Applied`; it
does not mutate the live controls or last snapshot. Reverting every live value
to the snapshot returns to `Applied`. Changing path text immediately clears
the validation key but retains the old snapshot as stale. Apply shares the
same derived guard as the renderer and defensively rechecks the executable
before showing confirmation.

Popup text may show the selected path. Activity entries use only `checked
current folder` or `paths omitted`, plus non-private start/safeguard values.

## Static write and process accounting

The hardened AST scan covers writer cmdlets and Windows PowerShell aliases,
redirections, sensitive writer/registry/XML types, static and instance writer
members, dynamic command calls, log-path interpolation, persistent-log consent
assignments, and the one documented official evidence link.

```text
STATIC_PARSE_ERRORS=0
FILE_WRITE_CALLS=1
ALLOWLISTED_ACTIVITY_LOG_WRITER=1
GAME_POLICY_WRITE_CALLS=0
WRITER_CMDLET_CALLS=0
REDIRECTION_WRITE_CALLS=0
SENSITIVE_WRITER_TYPES=0
UNAPPROVED_DYNAMIC_COMMANDS=0
RAW_PATH_ACTIVITY_CALLS=0
PERSISTENT_LOG_CONSENT_CONTRACT=PASS
DOCUMENTED_WEB_LINK_CONTRACT=PASS
STATIC_GAME_POLICY_WRITE_SCAN=PASS
```

The sole writer is `System.IO.File.WriteAllText` inside
`Save-ActivityLogSnapshot`. Its exact arguments are the explicitly chosen
activity-log path, the in-window activity text, and UTF-8 encoding. The guard
requires both explicit consent and a nonempty path. The only `Start-Process`
call remains the pre-existing user-clicked official Alpha 6 evidence URL; it is
not a game launcher or writer.

## Confirmation readability refinement

Following player-facing review of the native confirmation dialog, the preview
copy was reduced to decision-critical information without changing its state
machine or boundaries. The dialog now has deterministic text for each relevant
truth:

- First Apply: create-snapshot action, `Not yet applied`, start, checked
  folder, and whether Random safeguards are active.
- Changed reapply: apply-pending-changes action and only the actual changes.
- Unchanged reapply: refresh action, `No changes detected`, and the compact
  current-selection summary.

All three paths retain the preview-only/no-game-change guarantee. The dialog
uses `Game folder: checked` rather than exposing the raw path. Standard uses
the concise `Random safeguards: inactive` summary. The native WinForms Yes/No
button labels remain intentionally unchanged.

Post-refinement verification on 2026-08-14: Windows PowerShell 5.1 and
PowerShell 7 parse passed; the deterministic workflow suite passed 11/11 in
both hosts; direct and BAT smoke passed; the existing pure-contract suite
passed 56/56 in both hosts; and the AST static write scan passed in both hosts
with `FILE_WRITE_CALLS=1`, `ALLOWLISTED_ACTIVITY_LOG_WRITER=1`, and
`GAME_POLICY_WRITE_CALLS=0`.

## Remaining limitations and decisions

- Closing the preview discards the in-memory snapshot by design. The optional
  activity log is never read back as policy or session state.
- The persistent log uses the pre-existing bounded shell writer; full hardened
  module-host parity remains future work.
- This does not prove gameplay, save behavior, EAC, clean-client,
  accessibility, multiplayer, runtime, packaging, provider, or release
  readiness.
- No new owner decision was introduced. The four decisions already listed in
  `n0150.md` remain open and unchanged.
