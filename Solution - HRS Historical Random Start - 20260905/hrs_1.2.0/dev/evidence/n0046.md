# Phase 1A Chunk-Readiness Failure Analysis

Date: 2026-08-20
Decision: Root cause identified; source/build/live/run unchanged

The owner authorized read-only analysis of the first-load
`RELOC_CHUNK_NOT_READY` result. The exact probe branch was the pre-placement
check immediately after the one native `GetRandomSpawnPosition` call:

```text
candidate bounds -> IsChunkAreaLoaded(candidate) -> CanPlayersSpawnAtPos(candidate) -> SetPosition
```

Pinned `Assembly-CSharp.dll` IL shows that this ordering does not match the
game's native new-game/respawn lifecycle:

- `SpawnPointList.GetRandomSpawnPosition(world, null, 0, 0)` selects directly
  from the authored `SpawnPointList`; it does not require or load the candidate
  chunk.
- `PlayerMoveController.updateRespawn` consumes the selected position and calls
  `Entity.SetPosition(position, true)` without first calling
  `World.IsChunkAreaLoaded` or `World.CanPlayersSpawnAtPos`.
- `Entity.SetPosition(Vector3, bool)` is virtual, and
  `EntityPlayerLocal.SetPosition` overrides it.
- The local-player override calls `Origin.UpdateLocalPlayer`; for a sufficiently
  distant position this calls `Origin.Reposition`, allowing the chunk-observer
  lifecycle to follow the player to the destination.
- `World.IsChunkAreaLoaded` merely checks whether all chunks in the surrounding
  area are already synchronously present; it does not request them.
- `World.CanPlayersSpawnAtPos` returns false when the destination chunk is not
  present, so it is also unsuitable as a pre-placement readiness gate for a
  distant authored spawn.

## Smallest native-aligned correction

Preserve all one-attempt rules and change only readiness ordering:

1. Reserve before selection.
2. Select exactly one authored spawn candidate.
3. Reject undefined, invalid, or out-of-bounds candidates before placement.
4. Capture the semantic-before digest.
5. Call virtual `SetPosition(candidate, true)` exactly once.
6. During the existing bounded verification window, wait for candidate chunks
   to load and then require `CanPlayersSpawnAtPos`, positional equality, world
   equality, entity equality, and semantic equality.
7. Mark Completed only after all verification passes.

No explicit chunk-provider request, second random selection, retry, rollback,
teleport API, marker repair/removal, or persistence mutation is required. A
timeout or failed post-placement safety check leaves Reserved and stops.

This is native-aligned because the authored spawn list is consumed using the
same select-then-position ordering as the game's respawn controller, while the
probe retains stricter post-placement verification before completion.

No source, compiled artifact, staged payload, live Mod, or save was changed by
this analysis. The failed target remains Reserved and must not be reused.
