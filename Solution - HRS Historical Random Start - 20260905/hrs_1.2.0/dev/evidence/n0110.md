# Phase 1A Post-Placement Verification-Failure Analysis

Date: 2026-08-20
Decision: Verification-window defect proven; exact terminal predicate intentionally unresolved

The owner authorized read-only analysis of the unchecked-semantic
`RELOC_VERIFICATION_FAILED` result.

## Proven observations

- `RELOC_PLACEMENT_CALLED` occurred at runtime elapsed `80.142` seconds.
- `RELOC_VERIFICATION_FAILED` occurred at elapsed `81.167` seconds.
- The complete 120-`GameUpdate` window therefore lasted only `1.025` seconds.
- The redacted intervening game log confirms `PlayerSpawnedInWorld` and
  `Origin Reposition` immediately after placement.
- There was no teleport, placement exception, physics exception, or semantic
  result reason.

This proves virtual `SetPosition` executed and initiated the native local-player
origin lifecycle. It also proves that a fixed count of 120 `GameUpdate` callbacks
is not a meaningful chunk-streaming deadline on this client: updates ran at
roughly 117 callbacks/second during the settling interval.

The existing verifier combines context, entity, world, chunk readiness, safety,
and position tolerance into one boolean and emits only
`RELOC_VERIFICATION_FAILED`. Therefore existing privacy-safe evidence cannot
honestly distinguish which final predicate remained false at 1.025 seconds.
The analysis does not infer one as fact.

## Smallest safe amendment

1. Preserve exactly one reservation, selection, semantic-before capture, and
   virtual `SetPosition` call.
2. Retain the first-two-update delay, but replace the 120-update terminal limit
   with a monotonic wall-clock settling deadline (proposed: 30 seconds using
   Unity `Time.realtimeSinceStartup`).
3. Continue polling the existing combined acceptance conditions until they all
   pass or the wall-clock deadline expires.
4. On expiry, emit exactly one fixed categorical reason—context/entity/world,
   chunk timeout, unsafe destination, or position mismatch—without coordinates,
   distances, identities, hashes, or underlying state.
5. Capture semantic-after and mark Completed only after all original positional
   and safety conditions pass.

No retry, reroll, second placement, explicit chunk request, rollback, teleport,
respawn, marker repair/removal, or relaxation of safety/semantic acceptance is
required. A timeout still leaves Reserved and stops.

No source, compiled artifact, staged payload, live Mod, or save was changed by
this analysis. The failed target remains Reserved and must not be reused.
