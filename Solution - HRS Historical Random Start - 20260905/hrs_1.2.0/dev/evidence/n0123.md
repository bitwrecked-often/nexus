# Phase 1A Semantic-Digest Adjacent-Update Drift Analysis

Date: 2026-08-20
Decision: Temporal comparison defect identified; no state changed

The owner authorized read-only analysis of `RELOC_SEMANTIC_CHANGED`. No source,
payload, live mod, save, or game process was changed.

## Current capture interval

The deferred placement callback currently:

1. captures `semanticBefore`;
2. performs the one player placement and observer synchronization;
3. stores the snapshot and returns;
4. waits through subsequent game-update callbacks; and
5. captures `semanticAfter` only after chunk, safety, and position acceptance.

Runtime timestamps place `RELOC_PLACEMENT_CALLED` and
`RELOC_SEMANTIC_CHANGED` about 0.1 seconds apart. The digest therefore compares
two adjacent-update states, not the immediate pre/post effects of placement.

## Time-varying digest inputs

The digest intentionally includes exact representations of:

- player and stat health;
- stamina, food, and water floats;
- progression values including `XPGain`;
- item `UseTimes` and activation state;
- quest state/objective data; and
- active buff membership, flags, and `stackEffectMultiplier`.

Pinned native IL establishes independent time-driven update paths during that
interval:

- `EntityStats.Tick` and related stat-over-time processing;
- `EntityBuffs.Tick`, including per-buff `BuffValue.Tick`; and
- `Progression.Update`, which consumes `Time.deltaTime` and updates progression
  CVars/state.

Exact bitwise equality of the full digest across updates can therefore fail
without user action and without placement changing gameplay-semantic state.
The observed failure does not identify which private value changed, and no such
value is published.

## Smallest stronger proof

Retain the comprehensive digest inputs, but change only the temporal boundary:

1. in the deferred placement GameUpdate, capture `semanticBefore`;
2. call player `SetPosition(candidate, true)` exactly once;
3. synchronize the existing observer exactly once;
4. capture `semanticAfterPlacement` immediately, before returning control to
   another game update;
5. require digest equality then and emit the existing categorical unchanged or
   changed reason; and
6. only after equality succeeds, begin the containing-chunk verification
   window. Later verification must not recompare naturally ticking state.

This is a stronger causal test: it isolates synchronous effects of the actual
placement operation while retaining every current digest field. Chunk, safety,
position, completion, protected-tree, and persistence checks remain unchanged.
It adds no gameplay mutation, retry, reroll, second placement, rollback,
teleport, respawn, observer lifecycle operation, or chunk request.

The failed target remains Reserved and must not be reused.
