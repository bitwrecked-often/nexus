## 3. Frozen core product

```text
manual exact new-game name
  -> Standard or Random
  -> explicit Apply and readback
  -> direct-user-only Launch Game handoff
  -> exact-name and genuinely-new-player first-arrival gates
```

## 5. Bridge storage and schema decision

Use an owned sidecar inside the release mod folder so the launcher and runtime
share a narrow, inspectable boundary without parsing saves:

```text
mod/
  ModInfo.xml
  d0163.dll
  Bridge/
    policy.v1.json
    result.v1.json
```

Rules:

- `policy.v1.json` is launcher-written through same-directory staging, atomic
  replacement, immediate readback, and schema/hash validation.
- The runtime opens policy read-only, validates independently, and caches one
  immutable session intent. It never repairs malformed policy.
- `result.v1.json` is runtime-written through bounded same-directory staging,
  atomic replacement, and immediate readback. It is categorical evidence, not
  a command channel.
- Reject symlinks/reparse-point escapes, unexpected owner/identity, extra bridge
  files, oversize input, duplicate keys, unknown enum values, unknown schema,
  invalid UTF-8, and non-canonical game names.
- Never store Steam/platform IDs, player names, coordinates, tokens, save
  contents, machine-wide identifiers, or unrelated paths.

Minimum policy fields:

```text
schema = hrs-policy/v1
revision = monotonic unsigned integer
gameName = exact canonical user-entered name
mode = Standard | Random
enabled = false | true
writtenUtc = bounded UTC timestamp
policyDigest = digest of canonical controlling fields excluding this field
```

Semantic constraints:

- Standard requires `enabled=false` and grants no selector, reservation, or
  placement authority.
- Random requires `enabled=true` but still grants nothing unless every runtime
  environment, name, lifecycle, authority, lane, and marker gate passes.
- Apply succeeds only after byte/schema/readback verification and then reports
  `Historical Random Start enabled for <game name> — confirmed` for Random or
  `Standard start restored for <game name> — confirmed` for Standard.

Minimum result fields:

```text
schema = hrs-result/v1
policyRevision = exact consumed revision or zero when rejected before load
policyDigest = exact digest from the consumed policy
outcome = BYPASSED | RESERVED | COMPLETED | FAILED | INCOMPATIBLE | REJECTED
reason = allowlisted bounded reason code
markerState = ABSENT | RESERVED | COMPLETED | INVALID | NOT_APPLICABLE
observedUtc = bounded UTC timestamp
```

The launcher treats missing or invalid result evidence as `Runtime lane
unconfirmed` or a bounded unavailable result; it never guesses the cause and
never rewrites the authoritative in-save marker.

## 6. Manager-owned local management state

The portable manager keeps its non-game management state below its own support
root, not in Windows system locations:

```text
<ManagerRoot>/ui/HistoricalRandomStart_State/
  history.v1.jsonl
  recovery-index.v1.json
  snapshots/
  logs/                 # only under the approved local logging policy
```

Every attempt receives one correlation ID shared by visible notes, history,
snapshot metadata, and diagnostic logs. History includes successful, blocked,
failed, cancelled, reset, restore, launch-request, and Remove from Game events.
Recovery shows Default plus the five latest snapshot attempts. Failed or stale
attempts remain visible but disabled. A known-good target must pass immediate
revalidation before its specifically worded confirmation becomes actionable.

`Remove from Game` removes verified deployed game artifacts only. It retains
the portable manager and management state. Deleting the portable manager is a
separate manual user action and no Windows/system uninstall exists.

## 8. Safety invariants

1. If any 7 Days to Die client/server instance is running, all capsule-changing
   actions are disabled. Read-only views remain available. Do not queue work.
2. Steam is required only for `Launch Game`; Steam activity is not itself a
   mutation lock.
3. Only a direct local-user click can activate `Launch Game`. AI, automation,
   keyboard default acceptance, timers, and chained callbacks cannot do so.
4. The tool detects and explains the required non-EAC lane but never disables,
   lowers, configures, patches, bypasses, or stops EAC.
5. A crash triggers nothing. No service, watcher, tray, watchdog, supervisor,
   persistent lock, automatic cleanup, or automatic recovery exists.
6. One ephemeral single-instance guard is allowed. It must disappear with the
   process and carry no recovery behavior.
7. Unknown ownership, drift, schema, build, process identity, or runtime lane
   fails closed without widening inspection or mutation.
8. The base game, Steam, saves/worlds, Harmony/shared runtimes, other mods, and
   other Bit Wrecked solutions are external and untouched.

## 13. Alpha Core Completion Gate

The core is complete only when all are evidenced:

- direct exact-name Apply/readback for Standard and Random;
- truthful states and direct-user-only Launch behavior;
- Standard measured as zero custom gameplay action;
- Random measured as one guarded native authored-point relocation for one

- Completed persists across reload and prevents second action;

  Changes, and Remove from Game pass bounded tests;

- source/build/dependency/hash/scan/rollback evidence is linked and current;
