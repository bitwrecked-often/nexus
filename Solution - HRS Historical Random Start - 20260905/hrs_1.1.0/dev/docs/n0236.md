# Historical Random Start 1.1.0 release manifest

Release status: DEV candidate; live QA pending  
Solution lane: `hrs_1.1.0`  
Build identity: `1.1.0 / r110`  
Game target: 7 Days to Die V3.2 (b9), Navezgane, local single-player  
Anti-cheat: disabled (`SkipWithAntiCheat=true`)

## Why this version exists

`1.0.1` repaired package and DLL identification but retained a temporary fixed
selector for NG01. The release contract required both NG01 and NG02 to be
reachable through Random mode. `1.1.0` is the new feature lane that removes
that fixed control and implements actual selection between the two approved
points without modifying the preserved `1.0.1` candidate.

## Approved gameplay change

- Random consumes exactly one game-owned RNG draw per reserved new-character
  attempt.
- The draw selects one slot from the explicit approved index allowlist `{0,1}`.
- Slot 0 resolves NG01; slot 1 resolves NG02.
- The ten remaining Navezgane entries remain survey data and cannot become
  selectable merely because they exist in the source catalog.
- Selection still occurs after the environment, lifecycle, Standard-mode, and
  one-shot reservation gates and before deferred placement.
- The inherited malformed `START.bat` prefix was removed so the portable entry
  point begins with an exact `@echo off` command.

## Preserved behavior

- Standard mode performs no HRS relocation or trader mutation.
- Relocation remains one-shot and fail-closed.
- Terrain Y is resolved at runtime and safe landing uses the established native
  bounds, chunk, and `CanPlayersSpawnAtPos` checks.
- Optional arrival protection remains scoped to the existing reviewed snow
  behavior.
- The Journey to Settlement phase-one objective still routes to the nearest of
  the five reviewed Navezgane traders after a completed Random relocation.
- Existing characters, respawns, reloads, unrelated saves, other worlds,
  multiplayer, dedicated servers, EAC-enabled play, and incompatible builds do
  not gain new authority.

## Deliberately excluded

The six-certified-points-per-zone expansion remains in DEV scouting. The
generated POI catalog is candidate discovery data, not permission to add its
coordinates to this release. No DEV carousel or unscouted POI point is part of
the `1.1.0` release payload. A separately built QA-only full-POI carousel is
available for placement-health inspection under `dev`; it is excluded from
`d0163.dll` and from the release payload. See `n0238.md`.

## Required evidence before approval

1. Package, manager pins, metadata, runtime identity, release contract, and
   artifact hashes all agree on `1.1.0 / r110`.
2. Fresh Random games demonstrate NG01 and NG02 are both reachable.
3. Each approved point completes safe, stable, one-shot relocation.
4. Representative runs prove nearest-trader and starter-quest continuity.
5. Reload, ordinary death/reopen, Standard mode, unsupported-environment,
   installation, evidence-export, and rollback cases pass.
6. Promotion uses the exact DLL and metadata bytes approved by QA.
