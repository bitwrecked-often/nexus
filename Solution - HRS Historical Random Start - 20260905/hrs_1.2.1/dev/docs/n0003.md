# Historical Random Start 0.0.5 — Established Pipeline and Feature Map

Date: 2026-08-26
Status: CURRENT ARCHITECTURE BOUNDARY

## One Pipeline

```text
direct player action
  -> existing BAT / manager entry
  -> WinForms manager event
  -> validation and capability modules
  -> deployment and policy preparation
  -> direct-user-only launch boundary
  -> HistoricalRandomStartModApi.InitMod
  -> PlayerSpawnedInWorld handler
  -> environment / lifecycle / policy / marker gates
  -> Standard bypass OR bounded Random relocation
  -> sanitized result and local history/recovery projection
```

No additional main function, launcher, runtime entry, state authority, or
parallel orchestration path is authorized.

## Approved Extension Pattern

Every new feature must declare:

1. its owning existing stage;
2. input and output schemas;
3. exact filesystem or game-state boundary;
4. denial precedence and zero-action cases;
5. pure/static tests before live work;
6. removal or disable path; and
7. evidence state in the ledger below.

If a feature cannot use an existing stage, it has an architectural conflict and
must stop for owner review instead of creating another main.

## Feature Ledger

| Feature | State | Current evidence/constraint |
| --- | --- | --- |
| Exact-name Standard/Random contract | Pure-tested | Strict launcher/runtime policy vectors and state grid exist. |
| Standard no-op | Pure-tested/static-verified | No marker, candidate, or placement action in the Standard branch. |
| One authored-point Random relocation | Privately observed once | Historical Phase 1A evidence; not generalized reliability or release eligibility. |
| Exactly-once marker | Privately observed in proof lane; reload follow-up historically bounded | Do not infer current `0.0.5` runtime proof. |
| Functional manager-to-runtime bridge | Source implemented; non-live validation required | Existing manager, deployment, policy, runtime, result, history, and recovery source present. |
| `0.0.5` binary/package | Proposed/not built | Old generated output is retained historical evidence only. |
| Trader routing | Deferred | Requires separately opened proof and contract. |
| Biome safeguards | Deferred | Preview contract only; must not write global biome progression. |
| Discovery and All Games scopes | Deferred | Exact manually entered New Game name remains the core scope. |
| Multiplayer/dedicated/clean-client | Deferred/unproven | No compatibility claim. |
| Expanded coordinates, distance, drop, protection, rooftops | Deferred | Must not delay or fork the proven core pipeline. |

State meanings: `proposed`, `contract-defined`, `pure-tested`, `built`,
`privately observed`, `release-eligible`, or `deferred/rejected`. A feature may
advance only when its required evidence is recorded.
