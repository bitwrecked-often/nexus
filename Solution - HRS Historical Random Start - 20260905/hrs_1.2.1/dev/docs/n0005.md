## Windows PowerShell 5.1 Path Caveat

The first direct Windows PowerShell 5.1 run used the full descriptive active
lane path. Two suites created nested test paths beyond the legacy .NET
Framework `MAX_PATH` boundary:

- Alpha Core Contract: 86 pass, 2 path-host failures;
- Management State: 3 pass, 5 downstream path-host failures.

No functional assertion failed under PowerShell 7. The two affected suites
were rerun in Windows PowerShell 5.1 through a temporary `R:` drive alias that
resolved to the same active folder. They then passed 88/88 and 8/8. The alias
was removed with exit code 0, no `R:` drive remained, and no test residue was
left.

This is a legacy host/path-length limitation caused by the intentionally clear
version-folder name. It is not recorded as a product-code failure. Future
Windows PowerShell 5.1 validation from this lane should use an ephemeral short
path alias or an equally bounded short-path test harness.
