# Phase 1 First-Load Test Script 0.0.1

Date: 2026-08-20  
Status: Prepared; not executed

## Scope

Load the observation-only DEV probe once with EAC disabled, create only the
new disposable `Navezgane / HRS_Phase1_Test_001` game, observe the authoritative
spawn lifecycle log, exit normally, and compare protected state. This test does
not authorize relocation or any later phase.

## Automated preflight

Run `tests/p0225.ps1`. It must report:

- game closed;
- exactly the approved two-file owned payload;
- both live hashes match;
- target save absent; and
- launcher EAC setting disabled.

Any failure is an immediate abort.

## Exact launch

After separate owner authorization, run `tests/p0221.ps1`.
It repeats preflight and starts the visible client directly with:

```text
-force-d3d11 -nogs -noeac -logfile <fresh approved AppData log>
```

No Developer Mode, console command, cheat, server configuration, XML edit, or
existing save is used.

An authenticated Steam client session is a launch prerequisite. The first
authorized attempt proved that the probe loads and emits `OBS_READY`, but the
game then exited because Steam was not running/authenticated. That attempt did
not create the target save and is not a runtime observation failure. The user
must authenticate in the normal visible Steam client; test tooling never
handles or records credentials.

## Human interaction

1. At the main menu, confirm the game loads normally. Do not open an existing
   save.
2. Create a new local single-player game with world `Navezgane` and exact game
   name `HRS_Phase1_Test_001`.
3. Leave gameplay settings at their normal values; do not enable EAC, Creative,
   Developer Mode, or console commands.
4. Wait only until the new player has spawned and ordinary starter UI/quest is
   visible.
5. Do not die, reconnect, teleport, modify inventory intentionally, or continue
   gameplay during this first observation.
6. Exit through the normal menu and wait for the process to close.

## Expected evidence

- One sanitized `OBS_READY` line during module initialization.
- For the exact new-game callback, `authority=server`, `locality=local`,
  `lifecycle=NewGame`, `entity=true`, and
  `reason=OBS_ELIGIBLE_NEW_CHARACTER`.
- No `OBS_BUILD_MISMATCH`, `OBS_TARGET_MISMATCH`,
  `OBS_EAC_NOT_DISABLED`, `OBS_INTERNAL_FAILURE`, or raw private data.
- No probe-caused position, CVar, quest, reward, XP, gamestage, inventory,
  health, XML, Mod, or foreign-save change.

Use `tests/p0157.ps1 -LogPath <PHASE1_LOG>` to return only
validated `[HRS-P1]` lines. Do not copy or publish the raw game log.

## Abort conditions

Exit normally and stop if the module fails to load, any mismatch/internal
failure reason appears, EAC is enabled, the target name/world differs, an
existing save is selected, unexpected gameplay behavior occurs, or a raw path,
identity, address, coordinate, or exception appears in an HRS log line.

## Rollback

Before first target creation, rollback is removal of only the exact owned DEV
Mod folder. After the disposable target is created, preserve it for evidence
until post-test manifests are reviewed; do not delete it automatically. No
existing save or Mod may be changed or removed.
