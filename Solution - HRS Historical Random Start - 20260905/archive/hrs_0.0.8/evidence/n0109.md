## Lifecycle amendment

The synchronous `PlayerSpawnedInWorld` handler now performs only:

- exact environment/lifecycle/entity/marker validation;
- one Reserved marker write;
- one native random candidate selection and bounds validation; and
- creation of an in-memory deferred attempt with fixed context/candidate.

It emits `RELOC_PLACEMENT_DEFERRED` and contains no semantic capture, player
placement, or observer position mutation.

On the first later `GameUpdate`, the source:

1. revalidates compatibility, target, world identity, entity, and the existing
   observer;
2. captures semantic-before state after native respawn finalization;
3. calls player `SetPosition(candidate, true)` exactly once;
4. synchronizes the same existing observer exactly once;
5. marks the attempt placed and starts the 30-second deadline; and
6. returns, leaving verification to subsequent callbacks.

Placement exceptions stop with `RELOC_PLACEMENT_FAILED`. Changed deferred
context or a missing observer fails closed without selection or placement
retry. All containing-chunk, safety, position, semantic, and completion gates
remain intact.

No explicit chunk request, observer lifecycle call, reroll, second placement,
rollback, teleport, respawn, or marker repair was added.
