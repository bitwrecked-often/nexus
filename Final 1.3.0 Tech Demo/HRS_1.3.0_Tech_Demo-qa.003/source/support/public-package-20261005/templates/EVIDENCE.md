# Public review evidence

This archive shares the same product, source, native workbench, tests, history,
story, license and sanitized evidence with QA, customers and reviewers.
The current release is **1.3.0 Tech Demo**, candidate **1.3.0-qa.003**.
Its 46 independent cases and the human runtime campaign remain **Pending**.

`current/` contains bounded DEV evidence for this round:

- `runtime-chain/`: 58 source-control-flow scenarios and three detected broken
  copies. Actual callbacks and marker logic use controlled engine, resolver,
  compatibility, Harmony and result-I/O seams. Reload retains in-memory markers;
  it does not test real game save or quest serialization. Deliberate mutation
  failures establish detection and are not production defects.
- `manager/`: source-bound native-control, guard, settings-comparison, recovery
  and attribution checks. Receipt counts and identities govern each suite.
  The 97 callback, 86 focused and 26 repair checks retain their original manager
  identity. Candidate 003 carries this behavior evidence through an explicit
  verified presentation-only delta: the visible label is now **Game Name**.
  Current label, recipe compatibility and native rendering checks bind the new
  source. Those earlier suites were not rerun or relabeled as new passes.
  Controlled fixtures do not establish customer operation or real OS profiles.
- `native-event-loop/`: the real Windows PowerShell 5.1 STA ShowDialog host on
  the current display, including draft changes, repaint, resize,
  minimize/restore, activation and close, with recorded native events/errors.
  Editor returns are covered separately by the focused manager/layout checks.
  This is a bounded DEV host check, with no gameplay,
  customer Apply, launch, removal, Narrator or other display-scale qualification.
- `policy-chain/`: runtime codec, canonical migration/recovery and invalid
  writer checks, including preservation of an earlier policy on rejection.
- `build/`: the fresh qualified deterministic build from fifteen runtime
  sources and eight pinned b17 references. Only the project's runtime is shipped;
  proprietary game/reference assemblies are not included.
- `packaging-tools/`: generic and edition-specific release-tool fixtures.
  These verify tool behavior rather than independent QA of the final archive.
- `intake/` and `qa-return/`: authenticated return and preservation summaries,
  plus the returned DEV tasks, human plan and workstation completion plan.
  Their guided-session observations belong to the earlier 1.2.7 candidate.

Final callback or additional qualification receipts appear under `current/`
with their actual source identities. Inspected UI images, when included, live
under `current/inspected-images/`. Raw QA session metadata, private desktop
captures and local run directories are excluded.

The additional package record for Tech Demo candidate **001** verifies its
complete tree, root launcher and own QA tools. Its verifier diagnostic used
one controlled Windows slash correction and a shorter temporary root. The
corrected optional DEV verifier ships in candidate **002**; the 001 ZIP stays
unchanged. That earlier diagnostic is packaging evidence with its original
identity, not final-candidate gameplay or approval. Candidate **002** passes
independent verification with its unchanged shipped helper under default native
TEMP. Both original archives remain sealed. Candidate **003** includes the
owner's Game Name label correction. Qualified runtime/build reuse has an
explicit receipt; current manager changes have a separate exact delta receipt.

`prior-1.2.7/` preserves previously public records from the original frozen
1.2.7-qa.003 archive byte for byte, including earlier unsuccessful attempts and
their original scope. Its older case counts, candidate identities and content
manifests describe earlier rounds. They are historical evidence, not new passes.

[PUBLIC-PROJECTION.json](PUBLIC-PROJECTION.json) records original source and
public hashes for every copied input. Current prose/JSON receipts project
private workstation paths, link included counterparts portably, and remove
unavailable repository-link destinations;
executable source, runtime binaries and prior public records retain their bytes.
[PUBLIC-CONTENT-MANIFEST.json](PUBLIC-CONTENT-MANIFEST.json) authenticates the
prepared content subset. The root distribution manifest and public package
receipt authenticate the complete exported tree; final ZIP hash/extraction
receipts are recorded outside the immutable ZIP after export.

The [QA runbook](../QA-RUNBOOK.md) and frozen `context/dev/qa/cases.json` govern
fresh customer QA. Existing screenshots, source fixtures, build records and GUI
feedback do not establish terrain safety, damage protection, real save/quest
persistence, full Windows display/accessibility coverage or owner approval.
