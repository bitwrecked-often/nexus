# HRS 1.2.5 successor QA changes

The successor to frozen `1.2.5-qa.001` is being prepared for independent
customer-package QA. The active DEV manifest
records acceptance and the eventual export identity. These notes do not grant
gameplay approval or publication approval.

- The tested candidate target advances from V3.3.0 b14 to b17. Builds retain
  exact game, Harmony and compiler fingerprints and a deterministic double
  build. The frozen b14 candidate stays unchanged.
- Other game builds receive a best-effort attempt when the required runtime
  hooks are available. An incompatible hook leaves the normal start alone.
  Backward compatibility remains subject to separate version testing.
- A completed character's later death callback preserves the existing start
  result without another biome draw or relocation.
- Unverified runtime builds retain the `BUILD_UNVERIFIED` diagnostic instead
  of being mislabeled as an internal failure.
- Apply and Restore check that recovery settings can be stored before changing
  game files. Extract into a writable local folder outside OneDrive and linked
  folders. The warning gives the user an actionable next step.
- Launch guidance explains when settings must first be applied. A different
  game build alone does not require replacing or reapplying the same settings.
- The customer package now includes the existing **Bit Wrecked** application
  icon. Its bytes are required by the package allowlist and checked during
  export and isolated extraction.

Any, Chosen and Weighted selection, independent starting-biome protection,
placed trader routing and the five-attempt landing limit remain the 1.2.5
feature scope. DEV observations remain separate from the new archive's QA.
