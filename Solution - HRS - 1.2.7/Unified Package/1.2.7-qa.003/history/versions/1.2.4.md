## Placed-trader routing and fallback

The implemented route uses a real placed trader in the player's final landing
biome. If that biome has no placed trader, it chooses an existing trader in
another biome; it does not create or move a trader. Arrival hazard protection
remains tied to the landing biome, even when the chosen trader is elsewhere.
The intended boundary is that ordinary hazards apply after the player leaves
that protected biome. A targeted DEV test observed Burnt Forest hazard after
a protected wasteland start; the customer ZIP still needs independent QA.

The same-biome path has player-visible DEV acceptance on Navezgane and a
generated world. A controlled cross-biome DEV probe showed a marker to a real
other-biome trader; completing that cross-biome intro was not tested. If the
active world has no usable trader anywhere, HRS leaves a new character at the
vanilla start without claiming an intro route. If trader metadata is late,
HRS waits up to its bounded timeout; unavailable metadata is recorded
separately from a proven empty trader pool. Controlled DEV probes covered
the empty, late and timeout outcomes. These results are not customer QA or
evidence of natural failure frequency.
