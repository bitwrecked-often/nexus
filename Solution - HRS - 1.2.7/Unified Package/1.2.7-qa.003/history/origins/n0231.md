# Arrival-biome protection implementation manifest

Status: snow-first runtime proof implemented; live QA pending  
Solution: Historical Random Start `0.0.8.1`  
Initial proof target: Navezgane `NG01` / snow / Perishton  
Installed test build: 7 Days to Die V3.2 (b9)

## Objective

After a verified Random relocation, disable the environmental progression
debuff associated with that character's arrival biome. Preserve every other
biome hazard and avoid changes to unrelated saves, Standard starts, players,
vanilla XML, world files, inventory, equipment, and global game settings.

## Scope

The first implementation supports snow only. After the snow proof passes, the
same bounded pattern may be extended to:

| Family bit | Arrival biome | Native hazard family |
|---:|---|---|
| 1 | Burnt forest | `buffBurnt_Hazard*` |
| 2 | Desert | `buffDesert_Hazard*` |
| 4 | Wasteland | `buffWasteland_Hazard*` |
| 8 | Snow | `buffSnow_Hazard*` |

Pine forest and intentional water arrivals resolve to no protection.

## Architecture

### Launcher

1. Continue writing the exact game-name Random/Standard policy.
2. Explain that Random protects only the character's arrival-biome hazard.
3. Do not write vanilla configuration, save data, biome progression settings,
   inventory, equipment, or raw protection masks.
4. Display protection as active only after a matching runtime result proves it.

### Mod-owned XML

1. Add one hidden, namespaced protection buff per supported dangerous biome.
2. Each protection may suppress only its matching native hazard and storm
   family; it must not grant god mode, damage immunity, gear, XP, challenge
   completion, or economic value.
3. XML must be shipped inside the owned HRS mod folder through standard modlet
   configuration loading. Do not edit `Data/Config/biomes.xml` or
   `Data/Config/buffs.xml` in place.
4. Missing or renamed native buff dependencies fail closed before protection is
   claimed.

### Runtime

Protection is eligible only when all conditions are true:

1. installed build compatibility passes;
2. EAC is disabled and authority is local single-player server;
3. exact policy game name matches the active game;
4. policy mode is `Random`;
5. a genuinely new character completes verified relocation;
6. the arrival biome resolves to exactly one reviewed family;
7. the matching mod-owned protection buff is available.

After those gates, store a namespaced per-character protection value and grant
only the corresponding hidden buff. On reload, reapply only when the existing
Completed relocation marker and valid stored family agree. Never infer
eligibility merely from current position or current biome.

## Persistent state

Use game-owned per-character storage with namespaced nonzero values:

- existing relocation marker: `bitwrecked_hrs_state_v1`;
- new protection family: `bitwrecked_hrs_biome_v1`;
- permitted protection values: absent, `1`, `2`, `4`, or `8`;
- value `15` and all other values are invalid for starting-biome-only mode.

The protection value may be written only after relocation and landing
verification complete. A protection value without a Completed relocation
marker is invalid and grants nothing.

## Failure and removal behavior

- Any uncertain policy, marker, biome, buff, or persistence state grants no new
  protection and emits a bounded reason.
- A failed or restored relocation writes no protection family.
- Standard mode never writes, grants, refreshes, or removes protection.
- Death must not broaden or reroll the protected family.
- Reload may restore only the previously validated family.
- Removing HRS makes the hidden protection unavailable, restoring vanilla
  hazard behavior without editing the save or world.
- The implementation must not remove native progression rewards or mark native
  biome challenges complete.

## Snow-first proof

The first proof uses the signed `RandomSafe` policy selected by the main GUI
checkbox. After verified NG01 completion, runtime stores family `8` and
maintains only the native snow hazard/timer family. No vanilla XML is edited.
The earlier mod-owned XML approach remains an optional packaging refinement
after behavior is proven; it is not required for this runtime proof.

Use a fresh exact-name Navezgane game and the validated `NG01` Perishton street
landing.

Required observations:

1. relocation completes and the arrival biome resolves to snow;
2. stored protection value is exactly `8`;
3. snow hazard and snow-storm damage do not affect the eligible character;
4. snow weather, enemies, POIs, ordinary damage, hunger, injuries, and movement
   remain normal;
5. leaving and re-entering snow does not lose or broaden protection;
6. save/reload restores snow-only protection;
7. death/respawn does not reroll or duplicate protection;
8. a Standard game and an unrelated save retain complete vanilla snow hazards;
9. desert, burnt-forest, and wasteland hazards remain active;
10. removing the mod restores vanilla snow behavior.

## Test gates

Before live staging:

- XML parses and XPath targets are unique;
- all mod-owned names are namespaced;
- native family inventory matches the installed build;
- state-transition tests cover absent, valid, invalid, duplicate, reload,
  Standard, wrong-game, and failed-relocation cases;
- release static gate proves no vanilla writes and no global
  `BiomeProgression` mutation;
- PowerShell 5.1 launcher and deployment suites pass;
- deterministic double compilation passes;
- staged payload inventory and hashes match exactly.

## Rollout

1. Implement and test snow-only XML/state logic.
2. Run one disposable `NG01` live proof.
3. Audit reload, death, unrelated save, Standard, and removal behavior.
4. Generalize the proven pattern one family at a time.
5. Remove temporary controlled-location overrides.
6. Restore the full curated world-RNG pool only after location and protection
   matrices pass.

## Definition of done

Arrival-biome protection is complete only when it is character-scoped,
exact-game-scoped, persistent, reversible by mod removal, truthful in the
launcher/result evidence, and proven not to alter unrelated games or hazards.
